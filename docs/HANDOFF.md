## 2. Как подключить

> **Выполнено 2026-07-25 — раздел оставлен как история.** Актуальное состояние:
> обе папки лежат **внутри `frontend-nuxt/`**, а не в корне репозитория, и
> подключены алиасами `~calc` / `~content`. Из корня сборка на Railway падала:
> у фронт-сервиса Root Directory = `frontend-nuxt/`, соседние каталоги в
> контейнер не копируются. См. `PLAN.md` и `ARCHITECTURE.md` §4.

Калькуляторы импортируют JSON относительным путём `../content/*.json` — папки
`content/` и `calculators/` должны оставаться соседями (это по-прежнему верно:
перемещать их можно только вместе).

**Nuxt** — добавить алиасы в `frontend-nuxt/nuxt.config.ts`:

```ts
import { fileURLToPath } from 'node:url'

export default defineNuxtConfig({
  alias: {
    '~calc': fileURLToPath(new URL('../calculators', import.meta.url)),
    '~content': fileURLToPath(new URL('../content', import.meta.url)),
  },
})
```

Использование в компоненте:

```ts
import { taraFor, scoreEvent, splitTithi, weekdayRu } from '~calc'

const { data: horo } = await useFetch('/api/horoscope', { method: 'POST', body: birth })
const tara = taraFor(horo.value.nk.num, todayNakNo)          // тара-бала дня
const { tithi, paksha } = splitTithi(panchang.tithi.num)     // 1..30 → 1..15 + пакша
const score = scoreEvent({ eventId: 'wedding', janmaNo: horo.value.nk.num,
                           dayNakNo: todayNakNo, weekday: weekdayRu(date), tithi, paksha })
```

**Важно про размер.** `content/` — 1,4 МБ, из них крупнейшие: `planet_in_nakshatra.json`
(293 КБ), `nakshatras.json` (279 КБ), `padas.json` (128 КБ), `planet_stories.json` (134 КБ).
Целиком в клиентский бандл их тянуть не стоит — либо динамический `import()` по маршруту,
либо отдавать через API/Mongo. Мелкие таблицы калькуляторов (веса, тары, ганданта) —
единицы килобайт, их можно бандлить свободно.

**Проверено:** `tsc --noEmit --strict` на новом месте проходит без ошибок.

## 3. Состояние: что работает, что заглушка

Полный разбор — в [`COVERAGE.md`](COVERAGE.md). Кратко:

- 🟢 **Работает end-to-end:** накшатры (каталог + статьи), глоссарий, садхана,
  мантры, истории планет.
- 🟡 **Калькулятор готов, данные не подключены:** подбор события (в прототипе
  7 событий из 33 захардкожено), титхи, дома/знаки/положения планет, тара-школа,
  ретроградность.
- 🔴 **Лежит без дела:** `planet_in_nakshatra` (243 трактовки), `panchanga`
  (стоп-факторы!), `yogakarma`, `muhurta30`, `disclaimers`, `ui_texts`,
  `chart_geometry`, `sources`.

**Главное ограничение прототипа:** он на статических демо-данных. Ни один вызов
к API не сделан, формы рождения нет. Адаптеры `calculators/api-adapter.ts`
написаны и типизированы, но не вызываются.

## 5. Доменные правила, которые нельзя потерять

Проверены практикующим астрологом, подробности — в [`SERVICE-IA.md`](SERVICE-IA.md) §9.

1. **Панчангу нельзя разрывать.** Пять элементов (вара, титхи, накшатра, йога,
   карана) оцениваются вместе; стоп-факторы поднимать в вердикт дня — нельзя
   показать «накшатра хорошая», умолчав про активную Бхадру.
2. **Совместимость — всегда частичная.** Ашта-кута здесь 21 балл из 36 и не
   покрывает Мангала-дошу, бхакут, седьмые дома. Подавать как ориентир, не приговор.
3. **Тара-бала в подборе даты — фактор скоринга (вес 4)**, а не отдельный вердикт.
4. **Даши — часть натальной карты**, не отдельный раздел «периоды».
5. **Мягкий тон для чувствительного контента** — здоровье, «неблагоприятные» дни,
   нади-доша, Сад-сати, ганданта. Готовые формулировки — в `DESIGN-SYSTEM.md` §4.
6. **Спорное маркировать честно:** правило 27-й накшатры (школы называют 22-ю/23-ю),
   убывание силы тар по группам, веса подбора события — это методы школы, не канон.

## 6. Дизайн

`DESIGN-SYSTEM.md` содержит токены **двух тем** (тёмная «звёздная» из исходника +
светлая «пергамент») с переключением через `data-theme`, типографику, плотность
для простой/проф версий и решения: две градации границ (`--line` / `--line-strong`),
SVG-глифы планет вместо юникода, мягкий тон дисклеймеров.

Прототип `prototype/index.html` — эталон: открывается в браузере, обе темы,
переключатель аудитории, живые расчёты. Использовать как референс при вёрстке
компонентов, а не как код для копирования (он намеренно одностраничный и без Vue).
