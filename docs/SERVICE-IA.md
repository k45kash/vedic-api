# Информационная архитектура сервиса ведической астрологии

Итоговая карта экранов для двух версий (простая / профессиональная) с переключателем.
Синтез четырёх ролей (UX-аналитик, ведический астролог, проектировщик интерфейсов,
дизайнер) поверх кандидат-структуры. Расхождения между ролями разрешены явно (см. §12).

Первоисточники для реализации: `data/README.md` (инвентарь данных), `docs/CALCULATORS.md`
(алгоритмы/веса/пороги), `docs/NAKSHATRA-ARTICLE-MODEL.md` (18 секций статьи),
`data/chart_geometry.json` (SVG-геометрия), `data/filter_defs.json` (фасеты каталога),
`data/disclaimers.json` + `data/ui_texts.json` (тексты и пометки достоверности),
`calculators/` (готовые TS-калькуляторы). API: FastAPI в `PycharmProjects/Vedic`.

Обозначения: **[П]** — видно в простой версии, **[Про]** — добавляется/раскрывается в профи.
Без пометки — видно в обеих.

---

## 1. Модель продукта

Сдвиг от исходного HTML: там ~19 плоских разделов по типам данных и весь ввод руками
(«выберите свою накшатру»). Здесь — **6 интент-хабов** (задачи пользователя), а личные
данные приходят из API по дате рождения (вводятся один раз).

Один флаг `audience` (Пользователь / Астролог) управляет **сразу двумя вещами**:
1. **составом** — три проф-глубоких подвида скрыты в простом режиме;
2. **глубиной** — общие экраны в простом режиме показывают только ядро, в профи
   раскрывают дополнительные секции (пресет «видимых секций», а не разные страницы).

Дефолт — простой режим. Выбор «липкий» (хранится в профиле/локально), живёт в правом
верхнем углу шапки (mobile — в меню). Переключение не теряет контекст (та же накшатра/
дата, меняется детализация) и не теряет данные рождения. Проф-функции в простом режиме
**скрываются, а не тизерятся замочками** (решение UX, подтверждено).

Дисклеймеры достоверности управляются НЕ переключателем — видны обеим аудиториям (это
вопрос доверия): в простом режиме короче («ориентировочно»), в профи — с провенансом.

## 2. Онбординг и три режима профиля

Данные рождения (дата / время / место) вводятся **один раз** и питают все хабы через
клиентский стор (кэш ответа `/api/horoscope`). Не заставляем вводить при первом визите,
если пользователь пришёл в Справочник.

Форма (`BirthForm`): имя (опц.) · дата (обязательна) · время + чекбокс «время неизвестно»
· место → автокомплит города → координаты → `/api/tz` резолвит часовой пояс. Координаты
**не** кладём в URL (приватность).

**Три режима профиля** (критичная продуктовая развилка — время рождения знают не все):

| Режим | Условие | Доступно | Заблокировано |
|---|---|---|---|
| Полный | точное время | всё: лагна, дома, карта, даши | — |
| «По Луне» | время неизвестно | джанма-накшатра, «Обо мне», «Сегодня», тара, «Подобрать дату», «Совместимость» | лагна, дома, полная Карта (плашка «нужно время»); оговорка «на стыке накшатры возможна неточность» |
| Без данных | ничего не введено | Справочник целиком; «Совместимость» и «Подобрать дату» через ручной ввод накшатры (fallback к механике HTML) | «Обо мне» — только CTA-онбординг |

Принцип: **ни один хаб не показывает голую заглушку**, кроме «Обо мне». Везде деградируем
к общему/ручному режиму, а профиль допродаём баннером с конкретной выгодой (напр. «с датой
рождения учтём вашу личную благоприятность»).

## 4. Вкладки подробно

### 4.1. Обо мне / Моя карта
- **[П]:** герой-блок джанма-накшатры (`name`, `dev`, `symbol`, `span`, `shakti`, ссылка на
  полную статью) + строка лагны + список планет с трактовками (`placements.houses[slug]`,
  `placements.signs[slug]`) и достоинством (`dignity`). Персональная мантра+упайя.
- **[Про]:** SVG-карта домов сев./южн. стиля (`chart_geometry.json`), круг пад с D9-варготтамой,
  даши (Виншоттари), аспекты/соединения (`yogakarma.json`); в строке атрибутов — Варна, Доша,
  Враг-йони и пр.
- **Доменные требования (астролог):** держать **Лагну наравне** с джанма-накшатрой —
  персонализация не сводится к накшатре Луны. Даши держать здесь (натал), не выносить в
  отдельные «периоды». Пады [Про] показывать со знаком навамши (D9), иначе теряется смысл.
- **Оговорки в UI:** Whole Sign дома; достоинство по знаку без градуса экзальтации; ретро-флага
  в API пока нет.
- **Состояния:** пусто → CTA `BirthForm`; «время неизвестно» → лагна/карта затенены с бейджем
  «приблизительно», накшатра/планеты-по-знакам показаны; ошибка → «не удалось построить карту»
  + повтор; город не найден → назад в поле «Место».

### 4.2. Сегодня (дашборд)
- **[П]:** блок-вердикт личной тары дня (тара, качество, группа) + **панчанга дня как единое
  целое** + мантра дня. Точка входа для вернувшегося пользователя с профилем.
- **[Про]:** сила негативной тары (full/partial/mild), управитель накшатры дня; полная панчанга;
  30 мухурт; наватара-чакра (27×3 группы).
- **Блокирующее доменное требование (астролог):** панчангу **нельзя разрывать** — показывать
  все пять элементов (вара + титхи + накшатра + йога + карана) на дату, и **поднять наверх
  стоп-факторы** (Бхадра/Вишти-карана, йоги Вьятипата №17 / Вайдхрити №27, Раху-калам). День
  нельзя оценивать по одному элементу: активная Бхадра перечёркивает хороший остальной день.
  Разделять допустимо только «панчанга-на-дату» (расчёт, здесь) vs «панчанга-справочник»
  (энциклопедия, в Справочнике).
- **Состояния:** без профиля → общая панчанга дня доступна (не персональна), блок тары скрыт +
  баннер «добавьте дату рождения для личного дня»; `/calendar` упал → панчанга без личной тары.

### 4.3. Подобрать дату
- Вход: событие (33 шт.) + диапазон дат (дефолт +30 дней). Выход: список дней, отсортированный
  по `pct`, блок-вердикт (≥75 «Отличное», ≥55 «Хорошее», ≥40 «Приемлемо», <40 «Слабое») со
  значком стоп-фактора при срабатывании `vetoCap` (накшатра в избегаемых → 40%, рикта-титхи →
  30%, Амавасья → 20%).
- **[П]:** итог + галочки главных факторов. **[Про]:** построчный разбор весов (тара 4,
  накшатра 3, титхи 2, день 2, йога 1), какой фактор дал `±вес`, какой стоп-фактор ограничил.
- **Доменное требование (астролог):** личная тара-бала здесь — **фактор скоринга (вес 4)**,
  показывать её в связке с оценкой дня, не как отдельный несвязанный вердикт.
- **Оговорки в UI (обязательно):** это **оценочная модель школы** (`disclaimers.json` type=model),
  не каноническая формула. Расчёт **не включает Раху-калам и дневные каламы** — «сверьтесь с
  панчангой на время». Йога дня в API пока не считается (фактор опционален).
- **Состояния:** без профиля — работает по общей панчанге, тара-фактор отключён + подсказка;
  прогресс «проверено 12/31»; частичный сбой дат → показать посчитанные, пропущенные отметить.

### 4.4. Совместимость
- Партнёр А по умолчанию = «Моя карта»; партнёр Б — своя `BirthForm` **или** прямой выбор
  джанма-накшатры (`NakshatraSelect`, без времени/места).
- **[П]:** блок-вердикт (сумма/21, словесная оценка, флаг нади-доши — важнее баллов).
  **[Про]:** разбор 4 кут — Гана (6), Йони (4), Тара (3, в обе стороны), Нади (8).
- **Блокирующее доменное требование (астролог):** **не подавать как окончательный вердикт брака.**
  Всегда показывать «расчёт частичный (4 куты из 8, 21/36)»; ашта-кута ≠ полная мелапака (не
  учтены Мангала-доша/«манглик», бхакут, 7-е дома, даша-сампат, навамша обоих — это делает
  астролог). Нади-доша — «традиционно важный фактор, требующий внимания», **не** «брак невозможен».
  Йони-кута упрощена до 3 уровней. Порог 18/36 — «при отсутствии нади-доши», не абсолют.
- **Состояния:** работает без полного рождения (ручной ввод накшатр); если через `/horoscope` и
  API упал — предложить ручной выбор; заполнен один партнёр → кнопка disabled.

### 4.5. Практики
- **[П]:** «Мои средства» (упайя+мантра моей накшатры), справочник мантр/упай (`MantraBlock`:
  деванагари → IAST → рус → смысл + дисклеймер), истории планет + гимн Наваграха.
- **[Про]:** садхана-калькулятор (`sadhana.ts`): металл (4) + диапазон → День 1 (основное) /
  День 2 (доработки, `isFinishing`), жёсткое исключение дней по стоп-факторам.
- **Оговорки:** металл↔планета — классика; логика резервных дней/этапов — метод школы
  (`disclaimers.json` needs-check).

### 4.6. Справочник
- **Каталог накшатр:** сетка `NakshatraCard`×27 + поиск (14 полей) + фасеты (`filter_defs.json`:
  8 фасетов, primary = управитель+тип видны всегда, остальные 6 под «Ещё фильтры», single-select
  внутри фасета, AND между; тумблер «⚠ Гандантовые (6)»). В простом режиме «Ещё фильтры» свёрнуты.
- **Статья накшатры:** 18 секций (`NAKSHATRA-ARTICLE-MODEL.md`) со sticky-TOC. **[П] ядро:**
  шапка, катха, божество, ичха, символика, металл/камень, мантра, совместимость, профессии/места,
  тело/здоровье, упайя, цитата. **[Про] раскрывает:** астрономия, планеты-в-накшатре (интерактив),
  пады, даша, мухурта.
- **Прочее (рендер JSON без вычислений):** знаки, дома, планеты, панчанга-справочник, глоссарий;
  [Про] ретроградность, 30 мухурт, круг 108 пад; источники.
- **Крест-навигация:** из статьи → «Совместимость с этой накшатрой», «Мухурты этой накшатры»,
  «Тара-бала от этой накшатры».
- **Риск (UX):** Справочник рискует стать свалкой — обязательна внутренняя ИА (подразделы-табы
  внутри хаба, показаны выше). Это витрина для незалогиненного/SEO-трафика.

## 5. Сквозные модули (не вкладки)

- **Тара-бала** — живёт в «Сегодня» (личный фон дня) и внутри скоринга «Подобрать дату» (вес 4).
  Не отдельная вкладка (в HTML была разделом — профи будут искать; решается онбординг-тултипом).
- **Дисклеймеры достоверности** (`DisclaimerPanel`) — под каждым расчётным результатом, где
  `disclaimers.json.type ≠ verified`. Видны обеим аудиториям.
- **Тултипы терминов** (`TermTooltip` из `glossary.json`) — на всех экранах; снимают жаргон без
  ухода со страницы. Важнейший инструмент для простой аудитории.
- **Мантра-блок** (`MantraBlock`) — переиспользуется в статье, «Практиках», «Сегодня».

## 6. Навигация

- **Desktop:** верхняя горизонтальная навигация (6 хабов) + справа `ModeSwitch` [Пользователь |
  Астролог] и «Данные рождения». Проф-подвиды внутри вкладок помечены значком «✦ Про», в простом
  режиме свёрнуты/скрыты. Sticky-TOC (270px) — только на странице статьи, скрыт ≤900px.
- **Mobile:** нижний таб-бар из 5 (Обо мне, Сегодня, Подобрать дату, Совместимость, Справочник);
  «Практики» + служебное (Данные, режим) — в «Ещё»/бургер. `ModeSwitch` — в меню профиля.
- Каждый результат-вердикт имеет ссылку «почему / подробнее» → в справочную статью или проф-разбор.

## 8. Визуальная система (из design_tokens.json)

Тёмная «звёздная» тема, существующая — систематизируем, не изобретаем.

- **Роли токенов:** поверх сырых переменных `:root` — семантический слой: `surface/base`=`bg #0a0c12`,
  `raised`=`panel #12151f`, `card #161a27`; `text/primary`=`ink #e9e2d2`, `secondary`=`dim #a89c84`;
  `accent`=`gold #dcb45c`, заголовки=`gold2 #b8923a`.
- **Семантика good/bad/neutral** = `leaf #8fb27a` / `rose #c76b7a` / `sky #7fa8c9`, всегда с
  иконкой формы (не только цвет). Домены цвета (планеты/стихии/группы домов) — замкнутые
  категориальные шкалы, не переопределять семантикой.
- **Типографика:** сериф Iowan Old Style/Palatino для контента; иерархия строится **разрядкой +
  uppercase**, а не размером (фирменный приём — сохранить). H1 — золотой градиент clamp(40–66px).
  Числовые проф-таблицы (градусы, скоры) — служебный tabular-стек, чтобы засечки не «шумели».
- **Плотность простая vs профи:** одна тема, разный воздух. Простая — карточки, padding 18–20px,
  gap 24–28px, радиус 14–15px, один ответ на экран, детали под «Подробнее». Профи — таблицы,
  padding 12px, gap 12–16px, радиус 11–12px, tabular-nums, всё сразу, звёздный фон приглушить
  (opacity .45→.25).
- **Переключатель:** сегмент-контрол в шапке, активный сегмент — золотой градиент/рамка `gold2`;
  бейдж «Режим: Астролог» + fade-in появляющихся проф-секций как средовой сигнал.

**Долги доступности (обязательно учесть):**
1. `faint #6f6753` (~3.5:1 на bg) и fallback `#888` (~3.1:1 на card) **не проходят WCAG AA** для
   обычного текста — только крупное/декор/disabled. Значимый вторичный текст — минимум `dim`.
2. Границы `line #282d3e` (~1.4:1) слабы там, где рамка — единственный разделитель (сетка таблиц,
   контур инпута, сегменты карты) — усилить до ~`#3a4055` (≈3:1). Главный a11y-долг темы.
3. Тач-цели ≥44×44px. Двойное кодирование статуса (цвет + форма + текст).

## 9. Доменные правила (свод от астролога — обязательно)

**Блокирующее (иначе доменно неверно):**
1. Панчанга дня — единое целое (5 элементов + стоп-факторы наверх), см. §4.2.
2. Совместимость — всегда «частичный расчёт, не приговор», см. §4.4.
3. Дисклеймеры из `disclaimers.json` под всеми не-`verified` результатами; event-picker — явно
   «оценочная модель без Раху-калама».

**Связи (не разрывать):** тара-бала = фактор скоринга в «Подобрать дату»; даши — в «Моя карта»;
Лагна наравне с джанма-накшатрой; пады — со знаком навамши.

**Этика (обязательно в простой версии) — переформулировать из «приговора» в «зона внимания»:**
здоровье/болезни («конституция/склонности», не диагноз, дисклеймер «не медрекомендация»);
«неблагоприятные» дни/тары («день осторожности», + нюанс убывания силы негатива по группам);
нади-доша («фактор внимания», не «брак обречён»); Сад-сати («период дисциплины и зрелости», без
обратного отсчёта до «беды»); ганданта («тема трансформации», без фатализма).

**Спорное между школами — маркировать честно, не выдавать за канон:** правило 27-й накшатры в
таре (источники: 22-я/23-я); убывание силы тар по группам (метод школы); веса подбора события.

## 11. Приоритизация прототипа

**Флагманы (первая волна)** — покрывают весь стек интеграций (оба API + 3 из 6 калькуляторов)
и обе аудитории на общих экранах:
1. **Обо мне / Моя карта** — сердце персонализации, строит и валидирует пайплайн данных рождения.
2. **Сегодня (дашборд + тара + панчанга)** — ежедневный возврат, точка входа.
3. **Подобрать дату** — самый «продаваемый» сценарий (мухурта), уникальная механика скоринга.

**Вторая волна:** Справочник (рендер JSON, SEO-вход), Совместимость (механика есть, разовый
сценарий), Карта [Про] (SVG D1, `LagnaChart.vue` уже есть).

**Третья волна:** Мухурта-проф (30 мухурт, наватара-чакра), Садхана (нишевый), добор 4 недостающих
кут в совместимость.

## 12. Разрешённые расхождения ролей и принятые решения

| Вопрос | Позиции ролей | Решение |
|---|---|---|
| «Практики» — таб или распустить? | UX: распустить; астролог+проектировщик+дизайнер: оставить | **Оставить таб** + вынести мантры контекстно в «Обо мне»/«Сегодня» (ловит правоту UX) |
| Название хаба карты | UX: «Обо мне»/«Карта»; проектировщик: «Моя карта» | **«Обо мне» (простая) / «Моя карта» (профи)** — нейминг UX |
| «Сегодня» — таб или дашборд | UX: дашборд-точка входа; проектировщик: рядовой таб | **Дашборд** (для вернувшегося с профилем) |
| Панчанга: где | проектировщик развёл; астролог: собрать | **Собрать в «Сегодня»** (блокирующее правило астролога) |
| Канон цвета стихий | дизайнер: коллизия `ELEM_COL` vs `SADHANA_ELEM_COL` | **Канон `ELEM_COL`** на весь сервис; садхановый — только в легаси-блоке садханы |
| Светлый режим | дизайнер: отложить | **Отложить**; вместо него «dim/reading» для проф-таблиц |
| Сериф в числовых таблицах | дизайнер: tabular-стек | **Ввести** служебный tabular для чисел, сериф — заголовкам |
| Проф-функции в простом режиме | UX+дизайнер: скрывать, не тизерить | **Скрывать** |
