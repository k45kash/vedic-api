### Требует твоих действий 🔒

| Что | Где | Зачем |
|-----|-----|-------|
| Сервис MongoDB + **Volume на `/data/db`** | Railway | без вольюма данные стираются при редеплое |
| `MONGODB_URI`, `MONGO_DB`, `JWT_SECRET` | Railway → сервис API | подключение и подпись токенов |
| Почтовый отправитель (SMTP или сервис рассылок) | — | письма подтверждения и сброса пароля |
| Приложение Yandex OAuth | oauth.yandex.ru | `YANDEX_CLIENT_ID` / `SECRET` |
| Приложение VK ID | id.vk.ru | `VK_CLIENT_ID` (секрет не нужен) |
| Бот через @BotFather + привязка домена | Telegram | `TELEGRAM_BOT_TOKEN` / `USERNAME` |
| `OAUTH_REDIRECT_BASE`, `FRONTEND_URL` | Railway → сервис API | без них OAuth-редиректы уведут не туда |

**Пошаговая инструкция по всем провайдерам — [`OAUTH-SETUP.md`](OAUTH-SETUP.md).**
Там же важные предупреждения: VK требует верификации бизнес-профиля (от суток),
у Google секрет показывается один раз, а в Telegram нельзя нажимать «Switch to
OpenID Connect Login» — наш код работает по классическому HMAC-виджету.

`JWT_SECRET` сгенерировать: `openssl rand -hex 32`

#### Пошагово: MongoDB на Railway

1. В проекте Railway нажать **`+ New`** (или `⌘K` → «Database») → выбрать **MongoDB**.
   Поднимется официальный Docker-образ Mongo.
2. **Проверить вольюм.** Открыть сервис Mongo → вкладка с вольюмами. Если вольюма нет —
   создать: `⌘K` → «Volume» (или правый клик по канвасу) → выбрать сервис Mongo →
   mount path **`/data/db`**. Без этого база стирается при каждом редеплое.
3. Строку подключения прописывать **не нужно**: Mongo-сервис сам публикует `MONGO_URL`,
   приложение его понимает. Достаточно убедиться, что оба сервиса в одном проекте.
4. На сервисе **API** добавить переменные: `JWT_SECRET` (обязательно) и при желании
   `MONGO_DB=vedic` (по умолчанию и так `vedic`).
5. Для локальной разработки — скопировать публичную строку подключения из
   Mongo → Variables в свой `.env` как `MONGODB_URI` (внешний доступ идёт через
   TCP Proxy, включён по умолчанию).

### Где лежат content/ и calculators/ (важно, 2026-07-25)

Изначально они лежали в корне репозитория рядом с `frontend-nuxt/`, как
предписывал `HANDOFF.md`. **Пришлось перенести внутрь `frontend-nuxt/`** —
деплой падал:

```
Could not load /calculators/nakshatra (imported by composables/useJyotish.ts)
ENOENT: no such file or directory
```

Причина: у Railway-сервиса фронта Root Directory = `frontend-nuxt/`, и в
контейнер копируется **только эта папка** (в логе сборки — `copy / /app`).
Соседние каталоги репозитория в сборку не попадают. Локально всё работало,
потому что там весь репозиторий на диске — классический случай «у меня
собирается».

Почему не переключили Root Directory на корень: тогда Railway подхватил бы
корневой `nixpacks.toml`, а он от Python-бэкенда — фронт собрался бы не тем
сборщиком.

Проверка после переноса: сборка прогнана в песочнице, куда скопирована
**только** `frontend-nuxt/` (родительских каталогов физически нет) — проходит.

бэкенду придётся читать его из `frontend-nuxt/content/`, либо контент
переедет ещё раз — уже к бэкенду.

### Про защиту контента (задача 3.5)

Сейчас весь `content/` едет на клиент — то есть **полностью открыт**: файлы просто
лежат по URL, ленивая загрузка ничего не прячет. Это нормально, пока нет платных
тарифов, но становится проблемой ровно тогда, когда они появятся.

Важно понимать: **перенос в API сам по себе не защищает.** Публичный эндпоинт —
это то же самое, только на шаг сложнее. Защита появляется лишь при связке
«авторизация + ограничение частоты запросов», и даже тогда владелец аккаунта
может выкачать всё скриптом.

Поэтому настоящий довод — не «конкуренты украдут базу», а **платный тариф
должен что-то значить**: если премиум-трактовки лежат в бандле, любой
бесплатный пользователь читает их из исходников, и paywall — декорация.

Кандидаты на вынос (по убыванию ценности):

| Что | Почему |
|---|---|
| `picker_weights.json`, `tara_school.json` | **ноу-хау**: веса скоринга и метод школы ценнее текстов |
| `planet_in_nakshatra.json` | 243 трактовки, самый крупный уникальный актив |
| `nakshatras.json` (глубокие поля), `placements.json`, `yogakarma.json`, `muhurta30.json` | трактовки, вероятные кандидаты в премиум |

Оставить на клиенте: названия и короткие метки (нужны для самих расчётов),
`glossary.json` (это скорее маркетинг), дизайн-токены и `ui_texts`.
Выносить всё подряд вредно — каждый экран получит лишний запрос, а бесплатный
контент прятать не от кого.

**Хорошая новость:** все 14 загрузчиков в `useJyotish.ts` уже возвращают промис
(`() => Promise<T>`), поэтому замена `import()` на `fetch()` — одна строка на
файл, вызывающий код не меняется. Решение можно принимать выборочно и позже,
