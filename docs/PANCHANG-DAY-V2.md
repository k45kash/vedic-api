# Панчанга v2

Маршрут разработки — `/panchang-day-v2`. Контроль для сверок — Ставрополь, 27.11.2026, 03:00, UTC+3, видимые положения. Сравнение ведётся с `/panchang-day?date=2026-11-27&time=03:00`. Эталонную страницу и её API-контракт сохраняем.

| Задача | Критерий приёмки |
|---|---|
| Шкала | Один маркер с временем, активные интервалы выделены. Выбор минуты мышью, касанием и клавиатурой. |
| Сводка | Пять элементов и ближайший переход среди них видны до шкалы. Для перехода с секундами выбирается первая целая минута в новом интервале. |
| Мобильный вид | Горизонтальная прокрутка с закреплёнными названиями рядов; дополнительные ряды и карта раскрываются по запросу. |
| Раху-кала и Абхиджит | Полные интервалы сохраняются, пересечения выделены отдельно. |
| Календарь месяца | Титхи и накшатра на восходе, признак Бхадры в местные гражданские сутки. Клик открывает дату. |
| Ссылка для сверки | Передаёт город, координаты, выбранные дату, минуту, смещение и режим. |
| Часовые пояса | Проверяем смещение по городским координатам и дате. Точный расчёт суток перевода часов требует API с зоной IANA и хранением границ в UTC. |
| Оценки | Отображаем действующие справочники. Разницу с коллегами по Тритии и трактовку пересечения Абхиджит сверяем отдельно. |
| Персональная Тара-бала | Ряд рядом с накшатрой Луны и сводка для выбранной минуты используют сохранённый профиль рождения. При неизвестном времени сводка показывает все варианты натальной накшатры из профиля. Без профиля показана ссылка на его заполнение. |

## Журнал

1. Определены маршрут, контрольный пример и критерии проверки.
2. Реализованы маршрут v2, единый маркер, сводка, переход к ближайшей смене элементов, мобильные раскрывающиеся ряды и D1. Добавлены пересечения Раху-калы с Абхиджит, ссылка с параметрами и месячный API.
3. Браузерная проверка. На 03:00 ближайший переход — 07:19:03, Тритья → Чатуртхи и Вишти → Бава. Кнопка ставит 07:20, первую целую минуту после границы. В календаре 27 ноября видны Чатуртхи, Ардра и Бхадра. Ссылка содержит параметры контрольного примера. На ширине 390 px проверены раскрытие дополнительных рядов и загрузка D1.
4. Контроль исходной страницы выполнен побайтовым сравнением с опубликованным коммитом 73c3e3d. v2 собрана для локального просмотра. На Railway опубликован эталон.
5. В работе остаются переходы на летнее и зимнее время и сверка трактовок. Автоматический режим пока берёт смещение на местный полдень выбранной даты, применяет его ко всем суткам и к отображаемому месяцу. Трактовки сверяем после получения правил от коллег.
6. v2 опубликована на Railway из коммита 1545580. На стенде проверены дневная сводка, D1, календарь ноября и доступность эталонной страницы.
7. Реализован расчёт гражданских суток по зоне IANA. API в автоматическом режиме возвращает границы суток в UTC и интервалы с местным смещением. Календарь месяца использует отдельные границы для каждой даты. Ручной режим использует фиксированное UTC-смещение. Эталон обращается к прежнему контракту с фиксированным смещением.
8. Проверено в API и браузере. В Берлине 29 марта 2026 сутки длятся 23 часа, при открытии ссылки на пропущенные 02:30 отображается 03:00 с пояснением. 25 октября сутки длятся 25 часов. Оба вхождения 02:30 можно выбрать, а ссылка хранит конкретный момент в UTC. Границы всех рядов Ставрополя на 27 ноября совпали с эталоном. Сборка прошла, 419 тестов прошли и два дали ожидаемый сбой.
9. Дополнение доступно локально. Сверка трактовок Тритии и Абхиджит остаётся открытой, пока нет правил, которыми пользуются коллеги.
10. Для сверки добавлены пояснения к оценке Тритьи в двух пакшах и расчёт интервала Абхиджит вне Раху-калы. Расчёт явно показывает полное окно, пересечение и остаток. Оценка Тритьи соответствует текущему справочнику проекта. Правило коллег остаётся предметом сверки.
11. Изменения опубликованы на Railway из main (1bb1347). API вернул 25-часовые сутки для Берлина. В браузере на примере Ставрополя проверены пояснение к Тритье и окно Абхиджит вне Раху-калы 11:59–12:17.
12. Добавлено расписание «Переходы дня». В нём собраны пять элементов панчанги, восход, закат и границы Раху-калы и Абхиджит. Одновременные изменения собраны в одной строке. На сутках перевода часов время события подписано со смещением UTC. Кнопка времени выбирает первую целую минуту после события. Расписание свёрнуто при открытии страницы.
13. Расписание развёрнуто на Railway из main (a2749c9). На стенде для Ставрополя титхи и карана сгруппированы в 07:19:02. Выбор этого события обновляет сводку и D1 на 07:20. Локальный контрольный расчёт ранее возвращал 07:19:03.
14. В публичном меню и в кабинете «Панчанга» открывает v2. Для прежней страницы есть отдельный пункт «Эталон» в публичном меню и «Панчанга · эталон» в кабинете. При переключении через публичное меню переносятся дата и время из адреса страницы. Ссылка «Эталон для сверки» внутри v2 передаёт выбранные дату и время. На узком экране публичное меню прокручивается горизонтально.
15. Навигация опубликована на Railway из main (7cc1980). В браузере проверен переход из эталона в v2 и обратно для 27.11.2026, 03:00.
16. Панчанга перенесена в кабинет как единственная версия интерфейса. Старые адреса /panchang-day и /panchang перенаправляют на v2 с параметрами ссылки. Гостя отправляем на вход и возвращаем к расчёту после авторизации. Дневной и месячный API требуют действующую учётную запись. Общий /api/panchang сохраняет прежний контракт. Эталонный расчёт проверяется тестами в режиме фиксированного смещения.
17. Опубликовано в main и на Railway (2cfdfa4). На стенде оба специализированных API возвращают 401 без токена. Старая ссылка в гостевом браузере открывает вход с сохранёнными 27.11.2026 и 03:00. Локально API проверен с подписанным JWT. Всего 420 пройденных тестов и два ожидаемых сбоя.
18. «Подобрать дату» теперь передаёт в модель нитья-йогу на восходе и показывает интервалы Бхадры, пересекающие выбранные гражданские сутки. Бхадра предупреждает о конкретном времени и учитывается отдельно от балла дня. Ссылка из разбора передаёт в Панчангу дату, первую целую минуту на восходе или сразу после него, город и фиксированное смещение, использованное при подборе. Часовой отбор по длительности события остаётся отдельной задачей.
19. В браузере проверена связка на Москве 27 ноября. Подбор показал Шубху на восходе и Бхадру с вечера 26 ноября до 07:19. Ссылка открыла ту же дату и город на 08:28, с той же йогой. Сборка прошла. 421 тест прошёл, два дали ожидаемый сбой.
20. Связка опубликована из main (28109a9). Файл обновлённой страницы на Railway совпал с проверенной локальной сборкой.
21. Добавлен персональный ряд Тара-балы. Границы совпадают со сменами транзитной накшатры. Расчёт использует существующие справочник, формулу и варианты накшатры рождения. Расходящиеся оценки выделены нейтральным цветом. Для пограничной натальной накшатры показано пояснение о предварительном результате.
22. Проверено в браузере на Ставрополе 27 ноября 2026. С натальной Мригаширой в 03:00 показан Сампат, в 12:39 — Випат. При неизвестном времени рождения показаны оба варианта, Мригашира и Ардра. Без данных рождения видна ссылка на профиль. Сборка и тесты прошли.

23. Для каждой возможной накшатры рождения карточка показывает позицию, трактовку из справочника курса и отдельное предупреждение на 22-й и 27-й позициях. Предупреждение видно также в «Сегодня», Наватара-чакре и разборе подбора даты. Оценка тары и веса подбора даты сохранены.
24. В панчанге добавлен подбор времени по цели и длительности. Окна обрезаются границами местных гражданских суток и изменений учитываемых факторов. Выбирается первая целая минута, с которой помещается вся длительность. При неизвестном времени рождения требуют совпадения по цели для всех вариантов тары. Раху-кала, Бхадра, правило среды для Абхиджит и предупреждения для 22-й и 27-й позиций отображаются явно и понижают приоритет окна. Подбор ограничен перечисленными факторами.

## Подбор времени из списка дат

25. В Панчанге блоки «Тара-бала для вас», «Подобрать время внутри дня» и «Переходы дня» перенесены под таблицу интервалов. Над таблицей показаны выбранная дата с днём недели, соседние даты, «Сегодня», произвольный ввод даты, календарь месяца и местное время.
26. Подбор показывает первую и последнюю минуту допустимого старта включительно. Соседние подходящие отрезки учитываются вместе. Абхиджит сам по себе не ограничивает длительность. Для первого предлагаемого старта показаны переходы внутри события. На сутках перевода часов часы повторного времени подписаны со смещением.
27. Тара-бала, предупреждения школы, Раху-кала и Бхадра проверяются в выбранном режиме. Для подписания договора и старта проекта по умолчанию проверяется начало, для встречи и других дел из справочника — вся длительность. Это рабочая настройка интерфейса. Предупреждения снижают приоритет стартов. Список дат показывает до трёх диапазонов на дату с объяснениями и ссылками на Панчангу. Параметры цели, длительности и режима проверки передаются по ссылке.
28. Диапазон факторов времени загружается одним запросом `/api/panchang/tara-windows` и использует те же правила расчёта, что шкала. Подбор даты работает с фиксированным UTC-смещением места расчёта и передаёт его в Панчангу. Модель оценки даты на восходе сохраняется.

Открыто для методической сверки: какие виды дел требуют проверки Раху-калы, Бхадры и правила школы именно в момент начала, а какие на протяжении всей длительности. Пока режим явно выбирается пользователем и указан рядом с параметрами подбора.

29. Браузерная проверка с тестовым профилем. Для 27.11.2026 и длительности 60 минут первая ссылка в списке дат открыла 07:20 с диапазоном стартов 07:20–09:50 и сохранила режим проверки на всю длительность. Кнопка внутри Панчанги перевела фокус к шкале. Проверены переключение месяца, выбор даты и ширина 390 px. Пройдены сборка, проверка типов и 422 теста Python, два известных случая отмечены xfail.

30. Справа от «Минуты на шкале» добавлены стрелки предыдущего и следующего дня. Они используют ту же навигацию, что и верхний блок, и сохраняют выбранное местное время.

31. В подборе времени появились группы «Работа и проекты», «Путешествия», «Красота и уход», «Отношения». Новые цели используют общий ориентир из справочника Тара-балы, когда он применим, или показывают обзор общих факторов. Цель показывает, чего не хватает для отдельной оценки. Для подбора на двоих нужны второй профиль и правила сопоставления.
32. В режиме «Проверить выбранное время» оценивается текущая минута шкалы, включая предупреждения в выбранном режиме проверки. Длительности в новых целях служат редактируемыми настройками по умолчанию.

33. Подбор часа использует текущие интервалы титхи и йоги. Для целей, сопоставленных с событием справочника, переиспользуются те же оценки титхи с пакшей и бонусы йоги, что и в оценке даты. Стоп-титхи исключает окно, но показывается при проверке выбранного времени. При проверке всей длительности учитывается каждая пересечённая титхи, а бонус йоги действует, когда благоприятна каждая йога в интервале. Интервалы для остальных целей справочные. Стрижка использует правило справочника, окрашивание выделено в отдельную цель до уточнения методики.
34. Методика подбора часа ещё нужна для переговоров и встреч, собеседования и презентации, первого рабочего дня, публикации и рекламного запуска, окончания дел, приёмки и осмотра, подписания акта, заселения, окрашивания, маникюра и всех целей раздела «Отношения». Для охвата уже описанных в справочнике событий остаётся уточнить узкие подвиды, включая тип поездки и этап маршрута, вид ухода и спа, вид делового вопроса. Для совместного окна надо определить, как объединять оценки двух участников. Требуется отдельно подтвердить, какие правила школа применяет к старту и какие ко всей длительности.

## Общий каталог событий

35. «Подобрать дату» и «Подобрать время внутри дня» используют одни события и категории. У событий со справочной методикой сохраняется оценка дня на восходе. Для остальных показываем доступный подбор времени и прямо пишем, что правил оценки дня пока нет. Ссылка из подбора даты открывает то же событие в Панчанге. Старые ссылки с кодами целей продолжают работать.

36. Для проверки часа правила накшатры, вары, титхи и йоги применяются к интервалам, действующим на старте или на протяжении всего события. Стоп-фактор по накшатре или титхи исключает старт из подбора и остаётся видим при проверке выбранной минуты. Из каран учитывается Бхадра. Там, где для события есть фильтр по Тара-бале, нужен профиль рождения. Остальные общие условия доступны без него.

37. На сверку вынесены правила по остальным каранам, режим проверки для каждого события и правила оценки дат для дополнительных сценариев, например свиданий, маникюра и приёмки работ. Длительность и режим проверки можно изменить вручную.
