# Контент-модель: энциклопедическая статья накшатры

Спецификация для будущих страниц на Nuxt. Составлена по коду генератора статей
(`app.js`, секция `/* ---------- ARTICLES ---------- */`, строки ~642–766 архивной версии)
и данным `data/nakshatras.json`. Ничего не добавлено «от себя» — только структура,
реально присутствующая в исходнике.

---

## 1. Обзор

- **Что это.** Статья накшатры — длинная энциклопедическая страница об одной из 27 лунных
  стоянок. В архиве все 27 статей рендерятся циклом `DATA.forEach(...)` в один поток
  (`#articles`) с оглавлением-сайдбаром (`#toclist`); в Nuxt каждая статья — отдельная
  страница/роут (например, `/nakshatra/[no]`).
- **Количество:** 27 статей (записей в `data/nakshatras.json` — 27, ~60 полей каждая).
- **Источники данных:**
  - `data/nakshatras.json` — основной массив `DATA` (все текстовые и атрибутивные поля);
  - `data/planet_in_nakshatra.json` — слой `PLANET_LAYER`: объект `{ "1..27": [9 записей] }`,
    каждая запись — `{ planet, relation, special, core, notes[] }` (интерактивный блок
    «Планеты в этой накшатре»);
  - `data/glossary.json` — глоссарий, из которого строится `TERMMAP` для тултипов терминов;
  - `data/ui_colors.json` (в архиве — константы `RULER_COLORS`, `PLANET_COLORS`) — акцентные
    цвета по управителю и по планете.
- **Акцентный цвет статьи:** `RULER_COLORS[d.ruler]` (фолбэк `#b8923a`). Им красятся:
  заголовок-название, бейдж управителя, точка в пункте оглавления, рамка карточки сетки.

### Пункт оглавления (TOC)

Для каждой накшатры в сайдбар добавляется ссылка: `no` (с ведущим нулём) · `name` ·
цветная точка цвета управителя. Клик — переход/скролл к статье.

## 4. Механика тултипов терминов (TERMMAP / ALIAS)

- `TERMMAP` строится из глоссария (`GLOSSARY._groups[].terms[]`, источник —
  `data/glossary.json`): ключ — название термина `tm.t`, обрезанное до первой скобки
  или слэша (`tm.t.split(/[\(\/]/)[0].trim()`); значение —
  `{ skt: санскрит (если не «—»), lit: дословный перевод, d: описание }`.
- Применяется **только в строке атрибутов** (`.strip`): у каждого значения берётся
  **первое слово** (сплит по пробелу, `(`, `/`, `·`), и если оно есть в `TERMMAP`,
  всё значение оборачивается в `<span class="term" data-def="...">` с обработчиком клика.
  Текст подсказки: `skt — «lit». d` (санскрит и дословный перевод — если есть).
- Клик открывает попап `#term-pop` (заголовок = текст термина, тело = data-def,
  кнопка ×, закрытие по клику вне попапа). Позиционируется под элементом,
  прижимается к правому краю при нехватке места.
- `ALIAS` (словарь Дхарма/Артха/Кама/Мокша, Дэва/Манушья/Ракшаса, варны, доши) —
  **объявлен, но нигде в коде не используется** (мёртвый код). По смыслу это
  тождественные алиасы «значение → ключ глоссария»; в Nuxt либо не переносить,
  либо реализовать по назначению.

## 5. Карточка сетки (краткий вид, `renderGrid`)

Поля карточки `.gcard` (акцентный цвет — по управителю):

1. `no` (с ведущим нулём) + `name` + бейдж `ruler` (цвет управителя);
2. `span` (диапазон);
3. мета-строки: «Девата» → `devata`; «Символ» → `symbol`;
   «Гана · Йони» → `gana` · `yoni`; «Стихия · Цвет» → `element` · `colour` (фолбэки «—»);
4. бейдж «гандата», если `gandanta` есть и ≠ «Нет».

Клик по карточке — переход к полной статье. Обвязка сетки:

- текстовый поиск по конкатенации `name, devata, symbol, span, ruler, nature, gana,
  yoni, varna, element, dosha, purushartha, shakti, dev`;
- фильтры (`FILTER_DEFS`): управитель (`ruler`), тип/природа (`nature`) — первичные;
  под «ещё фильтры» — `gana`, `element`, `dosha`, `purushartha`, `varna`, `yoni`
  (значения нормализуются до базового слова);
- отдельный тумблер «⚠ Гандантовые (6)» по полю `gandanta`.

## 6. Рекомендации для Nuxt

### Общие (переиспользуемые) компоненты

- **`AttrStrip`** — сетка «ярлык → значение» с поддержкой тултипов терминов;
  используется дважды (атрибуты §3.1 и символика §3.2) — один компонент с пропсом-списком пар.
- **`TermTooltip`** — обёртка значения с подсказкой из глоссария (логика §4);
  пригодится и вне статьи (глоссарий — общий ресурс сервиса).
- **`MantraBlock`** — деванагари/IAST/русская транскрипция/смысл/гаятри + дисклеймер;
  та же структура мантр используется в других разделах архива (мантры планет, mantra_upaya) —
  делать общим.
- **`PadaList`** — список 4 пад; в архиве есть отдельный вид пад (`padas.json`),
  компонент общий.
- **`PlanetInNakshatra`** — чипы 9 планет + раскрывающаяся панель (relation/special/core/notes);
  данные из `planet_in_nakshatra.json`, цвета — общий словарь цветов планет.
- **`GandantaBadge`**, **`RulerBadge`** — мелкие общие атомы (условный рендер, цвет по управителю).
- **`SourceNote` / `DisclaimerFooter`** — унифицированная пометка достоверности:
  в статье их четыре вида (ичха-`src`, астрономия, даша, планеты) + пометки внутри текстов
  `metal`/`gem` «(реконструкция)». Стоит сделать единый компонент с типом
  («классика», «наука», «реконструкция», «пересказ»).
- **`NakshatraCard`** — карточка сетки (§5).

### «Простая» версия сервиса — что можно скрыть

Кандидаты на скрытие/сворачивание (проф. детали для практикующих):

- **Виншоттари-даша** (§20) — предсказательная техника;
- в строке атрибутов: **Варна**, **Гуна-триада** (и так пустая), **Доша**,
  **Враг (йони)**, **Сторона** — узкоспециальные;
- **Астрономия** (§9) — можно свернуть в спойлер;
- **Планеты в этой накшатре** (§19) — интерактив для продвинутых;
- **Мухурта** (§13) и **Пады** (§18) — по усмотрению (пады — скорее для продвинутых).

Ядро простой версии: шапка + шакти + катха + божество + ичха + символика +
металл/камень + мантра + совместимость + профессии/места + тело/здоровье + упайя + цитата.

### Прочее

- Двухколоночные ряды (§12–17) — на мобильных складывать в одну колонку (в архиве `.twocol`).
- Поле `guna` либо добавить в JSON, либо убрать ячейку «Гуна-триада» (сейчас всегда «—»).
- Неиспользуемые в статье поля `mantra` и `caste_note` (см. §7) — решить судьбу при миграции.

## 7. Несоответствия данных и кода (проверено скриптом по nakshatras.json)

1. **`d.guna` используется в strip («Гуна-триада»), но поля `guna` в JSON нет** —
   ячейка всегда показывает «—».
2. **Поля JSON, не используемые в статье (и вообще нигде в app.js):**
   - `mantra` — вероятно, устаревшее/дублирующее поле (мантры выводятся из
     `devata_mantra_*`);
   - `caste_note` — пояснение к варне, в UI не выводится.
3. `ALIAS` объявлен, но не используется (см. §4).
4. Дефолт `src`: при отсутствии поля подставляется строка «Тайттирия, пересказ».
5. `gandanta` со значением строки `"Нет"` трактуется как отсутствие ганданты —
   в Nuxt лучше заменить на `null`/boolean + текст.
